# 妙搭报名页迁移设计

## 背景

当前 LIVE Studio Local Data Access 报名页位于 VitePress 文档站中，由 `DeveloperApplication.vue` 提供中英文三步表单，通过 Formspree 提交。此次迁移将报名能力从文档站解耦，形成独立维护、独立测试和独立部署的应用。

## 目标

- 新建私有 GitHub 仓库 `tiktok-live-studio-developer-application`。
- 从现有项目迁移报名页，不迁移文档、协议、示例和礼物目录。
- 保留中英文、三步表单、响应式布局、键盘可访问性和现有 TikTok 视觉风格。
- 使用妙搭全栈应用部署公网报名页。
- 使用妙搭服务端接口将报名记录写入新建的飞书多维表格。
- 完成一次真实测试报名，并核对多维表格中的完整记录。

## 非目标

- 不修改或下线现有 Cloudflare Pages 站点。
- 不在本次迁移中调整申请审核流程、凭证发放流程或通知机制。
- 不迁移文档站导航、搜索、开发文档、Demo 和 Agent Skill。
- 不在浏览器中直接调用飞书 OpenAPI，也不向前端暴露任何应用凭证。

## 系统边界

系统由三个边界清晰的单元组成：

1. **报名页前端**：收集用户输入、执行逐步校验、展示提交状态，不持有飞书凭证。
2. **妙搭服务端接口**：校验和规范化请求、处理幂等与重复提交、调用飞书 OpenAPI。
3. **飞书多维表格**：保存报名记录，供运营人员筛选、审核和协作。

新仓库只维护前端、服务端接口、自动化测试、部署配置和项目说明。原文档项目保持不变，仅作为迁移源。

## 技术方案

采用本地代码开发的妙搭全栈应用。

- 前端使用 Vue 3、TypeScript 和 Vite。
- 从现有 `DeveloperApplication.vue`、`developer-application.css`、`application-submission.mjs` 及必要图标中提取可复用实现。
- 移除 VitePress 运行时依赖，提供独立根路由。
- 默认根据浏览器语言选择中文或英文，并提供显式语言切换。
- 前端提交地址替换为同源 `POST /api/applications`。
- 服务端以环境变量或妙搭安全配置持有飞书应用凭证和 Base 标识。
- 服务端调用飞书 OpenAPI，在 `Applications` 数据表中新增记录。
- 妙搭运行时可见范围设置为公开，以支持未登录外部用户访问。

## 页面行为

页面保留现有三个步骤：

1. 关于申请人：姓名、工作邮箱、国家或地区、团队或公司、角色、TikTok 用户名。
2. 关于项目：项目名称、项目描述、技术栈、测试时间、演示链接。
3. 数据需求：事件类型、互动设计、补充说明、联系同意。

客户端规则：

- 每一步只校验当前可见字段。
- 至少选择一种直播事件。
- 提交期间禁用前进、后退和提交操作，避免重复点击。
- 请求失败时保留全部填写内容。
- 请求超时或结果不明确时不自动重试。
- 成功后隐藏表单，展示服务端返回的 `Application ID`。
- 蜜罐字段非空时拒绝提交，并提示用户检查自动填表插件。

## API 契约

### 请求

`POST /api/applications`

请求体使用 JSON，仅接受以下白名单字段：

- `fullName`
- `workEmail`
- `countryOrRegion`
- `teamOrCompany`
- `role`
- `tiktokUsername`
- `gameName`
- `gameDescription`
- `technologyStack`
- `demoUrl`
- `testingTimeline`
- `eventTypes`
- `interactionDesign`
- `additionalNotes`
- `locale`
- `consent`
- `honeypot`

服务端执行必填、类型、长度、邮箱、URL、枚举值和蜜罐校验。未知字段被忽略，不记录请求头、Cookie 或用户填写内容到普通日志。

### 成功响应

```json
{
  "ok": true,
  "applicationId": "APP-20260918-XXXXXX",
  "deduplicated": false
}
```

### 错误响应

| HTTP 状态 | 错误码 | 含义 |
| --- | --- | --- |
| `400` | `VALIDATION_ERROR` | 字段校验失败 |
| `409` | `SUBMISSION_CONFLICT` | 无法安全处理重复请求 |
| `429` | `RATE_LIMITED` | 提交频率过高 |
| `502` | `BASE_WRITE_FAILED` | 多维表格写入失败 |
| `504` | `SUBMISSION_UNCONFIRMED` | 写入结果无法确认 |

错误响应不包含飞书凭证、内部堆栈或完整上游响应。

## 幂等与重复提交

- 客户端为每次明确的提交动作生成幂等键，并随请求发送。
- 服务端以幂等键作为首要判定依据。
- 同一工作邮箱与项目名在短时间窗口内重复提交时，返回已有 `Application ID`，不新增记录。
- 上游超时后不盲目重试写入；接口返回 `SUBMISSION_UNCONFIRMED`，提示用户联系支持邮箱确认。

## 多维表格模型

新建多维表格，并创建 `Applications` 数据表：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `Application ID` | 文本 | 服务端生成，唯一 |
| `Submitted At` | 日期时间 | 服务端生成 |
| `Status` | 单选 | 默认 `Pending` |
| `Full Name` | 文本 | 必填 |
| `Work Email` | 文本 | 必填，邮箱格式 |
| `Country or Region` | 文本 | 必填 |
| `Team or Company` | 文本 | 可选 |
| `Role` | 文本 | 必填 |
| `TikTok Username` | 文本 | 可选 |
| `Game Name` | 文本 | 必填 |
| `Game Description` | 多行文本 | 必填 |
| `Technology Stack` | 单选 | 必填 |
| `Demo URL` | URL | 可选 |
| `Testing Timeline` | 单选 | 必填 |
| `Event Types` | 多选 | 至少一项 |
| `Interaction Design` | 多行文本 | 必填 |
| `Additional Notes` | 多行文本 | 可选 |
| `Locale` | 单选 | `en` 或 `zh-CN` |
| `Source` | 文本 | 固定为妙搭报名页 |
| `Consent` | 复选框 | 必须为真 |

## 安全与隐私

- 飞书 `App ID`、`App Secret`、访问令牌和 Base 标识只保存在服务端安全配置中。
- 仓库不提交 `.env`、凭证文件、真实报名数据或测试用户隐私信息。
- 前后端均限制输入长度，服务端再次校验所有字段。
- 服务端日志只记录请求 ID、结果码、耗时和脱敏错误信息。
- 公网发布前检查妙搭应用访问范围；公开仅代表可打开页面，不授予 Base 访问权限。

## 测试设计

### 单元测试

- 字段规范化和白名单。
- 必填、邮箱、URL、枚举和长度校验。
- 蜜罐拒绝。
- 幂等键和重复记录判定。
- 飞书字段映射。
- 上游错误到公开错误码的映射。

### 浏览器测试

- 中英文完整三步流程。
- 桌面端和移动端布局。
- 键盘导航、焦点移动和可访问状态。
- 返回上一步时内容保持。
- 至少选择一种事件。
- 重复点击只产生一个请求。
- 成功、明确失败和结果不明三种状态。

### 集成验收

- 使用测试身份提交一条标记清晰的真实报名。
- 核对多维表格全部字段、提交时间、状态和申请编号。
- 使用无登录窗口打开妙搭公网链接并完成提交。
- 验收后删除或标记测试记录，避免进入真实审核队列。

## 仓库与交付

- 仓库名：`tiktok-live-studio-developer-application`。
- 可见性：私有。
- 默认分支：`main`。
- 首次迁移保留可追踪的提交历史，但不复制原文档仓库的无关 Git 历史。
- README 说明本地开发、测试、妙搭初始化、环境变量和发布流程。
- 最终交付包括私有仓库、妙搭管理入口、妙搭公网链接和多维表格链接。

## 实施顺序

1. 建立独立本地项目并先编写关键行为测试。
2. 迁移前端组件、样式、字体和必要素材。
3. 实现服务端校验、幂等和 Base 写入适配器。
4. 新建多维表格并配置字段。
5. 创建妙搭应用，初始化本地全栈项目并配置安全变量。
6. 运行单元测试、构建和浏览器测试。
7. 创建 GitHub 私有仓库并推送 `main`。
8. 发布妙搭应用并设置公网可见。
9. 执行一次真实端到端验收并核对 Base 记录。

## 完成标准

- 新仓库只包含报名应用及其必要资源。
- 本地测试、构建和浏览器测试通过。
- 妙搭公网链接可由未登录用户访问。
- 中英文报名均能成功写入新建多维表格。
- 页面不会暴露飞书凭证，也不会在错误日志中记录完整报名内容。
- 一次真实测试提交在 Base 中形成且仅形成一条完整记录。
